# Prelude v2 — zuverlässig das Richtige einspielen: Bauplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Vor jedem Arbeitsprompt in Claude Code spielt der Mod `prelude-gate` die ein bis zwei wirklich passenden Learnings (mit Kernsatz), Skills und Capabilities in den Kontext ein — gemessen besser als heute und ohne Irreführung.

**Architecture:** Drei Repos. (A) Der Atlas-Daemon bekommt additive Suchfilter (mehrere Quellen, Präfix, `as_of`) und liefert Datum, `superseded_by` und Kernsatz je Treffer. (B) Im `prompt-prelude`-Repo entsteht der gemeinsame v2-Vertrag (Töpfe, Anfragebau, Gate-Prompt) als Python-Quelle, die per Generator in den Mod gespiegelt wird, plus die Messbank `replay/bank.py`. (C) Der Mod `prelude-gate` führt die Pipeline im `prompt.submit`-Handler vor `next` aus (harte Grenze 4 s), protokolliert im Modus `shadow` und hängt im Modus `live` einen Block an `e.context`. Live-Schaltung und Abbau des alten Hooks sind Owner-Gates (D).

**Tech Stack:** Python 3.12 (Atlas, prompt-prelude, pytest), TypeScript-Mod-API von Claude Code 2.1.303 (`claude plugin test|validate`, `tsc`), Haiku über `$.model.complete`, Opus-Gutachter über Workflow-Agenten.

**Spec:** `docs/superpowers/specs/2026-10-19-prelude-einspielen-design.md` (dieses Repo, Commit `fe851c4`).

## Global Constraints

- Zeitbudget **harte Grenze 4 s** je Prompt ab `prompt.submit`; danach nichts einspielen, Grund protokollieren (`reason: "budget"`), kein Ausweichen auf eine Notsuche.
- **Genau ein Modellaufruf** je Prompt: Haiku (`config.model`, Standard `haiku`) prüft; der Anfragebau ist regelbasiert.
- Töpfe und Höchstzahlen je Prompt: `learnings` ≤ 2, `skills` ≤ 2, `capabilities` ≤ 2; beim ersten Prompt einer Sitzung `learnings` ≤ 3. „Nichts“ ist erlaubt.
- Learnings-Quellen: `agent-memory/` (Learnings und Patterns), `native-` (Claude-Erinnerungen), `codex-native/`, `shared-memory/`, `membrain/`; `haupt-wiki/queries/` nur nachrangig. Skills: `atlas/skill:`, `atlas/subagent:`; Capabilities: `atlas/mcp-server:`, `atlas/plugin:`.
- Nie einspielen: Treffer mit `superseded_by` oder abgelaufenem `valid_to` (der Daemon blendet `valid_to` aus; der Client verwirft zusätzlich jedes `superseded_by`), `review=rejected` (blendet der Daemon aus).
- Rahmung des Blocks wörtlich: `Hinweise aus früheren Fällen und passende Werkzeuge — prüfen, nur nutzen, wenn sie zur Aufgabe passen.`
- Prompt-Klärung nur, wenn Haiku `clarify` liefert; Ausgabe als `vermutlich gemeint: …` neben dem Prompt, nie als Ersatz.
- Nur `origin.kind === 'composer'`, interaktiv, kein `e.command`, kein `e.isMeta`; Codex und `claude -p` bleiben außen vor.
- Atlas-Aufrufe tragen `caller: "prelude-gate"`.
- Zeilenenden: Mod-Dateien LF (`.gitattributes eol=lf`); neue Dateien im `prompt-prelude`-Repo CRLF; Atlas-Arbeitsbaum CRLF (Index LF). Vor jedem pytest: `C:/Users/domes/dynamic_central_orchestrator/.venv/Scripts/python.exe C:/Users/domes/.claude/skills/sqlite-schema-guard/scan.py <repo>` muss PASS sagen.
- Das `prompt-prelude`-Repo ist öffentlich: Prompts, Prompt-Paraphrasen und Learning-Texte nur unter gitignorierten `replay/data/`; ins Repo nur Code und anonyme Kennzahlen.
- Modelle: Haiku im Gate (wie live), Opus als Gutachter der Messbank, nie Fable.
- Kein Push, kein Daemon-Neustart, keine `settings.json`-Änderung ohne Owner.

## Review Focus

1. **Daemon weg oder langsam** → Prompt geht nach spätestens 4 s unverändert durch, nichts eingespielt, `reason: "daemon"|"budget"` im Protokoll (Task C2).
2. **Alter Daemon ohne Erweiterung** (Runtime noch nicht aktualisiert) antwortet auf eine `source_system`-Liste mit 400 → der Client fällt auf eine Suche je Quelle zurück und bleibt funktionsfähig (Task C2).
3. **Haiku antwortet kaputt** (kein JSON, unbekannte `cid`, leerer Text, `aborted`) → nichts eingespielt, kein Fehler im Prompt (Task C1).
4. **Learning-Text mit eigenen Anweisungen oder Markup** (`</prelude>`, „ignoriere vorherige …“) → im Block neutralisiert und gekürzt, kann den Rahmen nicht schließen (Task C1).
5. **Sehr langer oder eingefügter Prompt, Windows-Pfade, Code, Umlaute** → Anfragebau entfernt Pfade/Code, kappt auf `PROMPT_CAP`, behält Umlaute (Task B1).
